# Current Aimlabs GraphQL discovery

On **2026-09-29**, the public Aimlabs website's [application bundle](https://aimlabs.com/_next/static/chunks/pages/_app-236ef93a88d9fbfd.js) identified `https://api.aimlabs.com/graphql` and issued queries through its `Trainer` root. `get-graphql-schema https://api.aimlabs.com/graphql` then returned [the full current SDL](aimlabs-current-schema-2026-09-29.graphql) in one request (SHA-256 `93a9570fb03f572137196de33a01aeaaa10b45fb47ffc2218e9fc5fb02c5ad15`, 15,191 lines). This endpoint is distinct from the older `https://api.aimlab.gg/graphql` used by the viewer. The official bundle itself has a SHA-256 of `d0eee401f1afa26e32ce0e88dc743cf7c2e5e773f3b301b48d7726da3e2b8efa` in the sampled build.

The SDL contains **1,290 definitions**, including 825 `Trainer_` definitions, 256 `contentful_` definitions and 13 `Auth_` definitions. `TrainerQuery` has 129 fields, compared with 60 in the archived root `Query`. The archived `Aimlab` object still has 18 fields in its current `Trainer_Aimlab` counterpart; most new reachability is through the larger root, profile, play and connected types. [The name-based structural delta](aimlabs-current-schema-delta.tsv) records 351 new `Trainer_` type names, 362 added members, 11 removed members, 14 changed member signatures and 6 old names without a current `Trainer_` counterpart. It normalizes the `Trainer_` prefix, argument order and old `Query`/`Mutation` names; a renamed type can appear as removed and added.

Contract changes that affect callers include `PlayFilterInput.mode` changing from `Float` to `Int`, optional `app` selectors on profile task stats and username, `Play.taskSlug` becoming non-null, and `universalSensFinderData` changing from a single object to a paged connection with required input. The old `LeaderboardInput.scoreToProjectRank` is gone; the current input has separate projection statistic and value fields. The delta lists every signature change and removal.

**A schema field is a capability to ask, not evidence that anonymous users can read useful values.** The [live inventory](aimlabs-data-inventory.md) records bounded runtime responses, including nulls, authentication failures and rate limits. Neither `contentful_` website content nor private `Auth_` account fields are player telemetry.

## Typed analytics whose names are now known

The current SDL resolves the formerly unknown `AthenaMetricTimeframeRange` values to **`DAYS_7`, `DAYS_30`, `DAYS_90`**. `AthenaMetricBase` distinguishes `GLOBAL` (one sample per play) and `TIMED` (time-window samples). Metric field types include boolean, enum, numeric, arrays, time range and vector; fields can be stored as base columns or `extraData`. The `athenaMetricDefinitions` root returns metric names, descriptions, field definitions and coaching instructions **in the schema**, but an anonymous request returned `UNAUTHENTICATED`.

`AimlabProfile.athenaMetricTimeseries(metricId,range)` defines one UTC day per point, oldest first. Each point has play/sample counts, optional mean metric value and severity, minimum/maximum, time coverage and a share above a server-selected severity threshold. Flicking metrics add overshoot, undershoot, perfect and direction-error aggregates. `athenaMetricInsight(range)` defines strengths and weaknesses with contributing play IDs and counts. Both profile paths returned `UNAUTHENTICATED` anonymously; they cannot support a public chart on present evidence.

## Replays and leaderboards

`publishedReplay(replayId)` and `replayFeed(feedId)` are new root paths. `AimlabReplay` has publisher, title/description, tags, task, thumbnail, published/deleted timestamps, comment permission and engagement counts. Replay comments have an author and a timestamp **in seconds from replay start**; comments and feed entries may be paged. These are social publishing records, separate from the signed Avro telemetry URL on `PlayManifest`. A known published replay answered anonymously with 56 views, no likes/comments and comments enabled. A replay's presence in a play record does not establish that it is publicly published.

Leaderboard input now includes device, multiplayer, multiple user IDs, benchmark season, academy plan, stars and projection statistic. Team entries can contain constituent player entries. Projection can report rank, percentile, minimum score and total rows; the SDL documents that rank may be `0` below the top 100 and percentile `0` for boards with fewer than 100 records. Those sentinel meanings are **not** ordinary rank zero. The older task board and a bounded season board answered anonymously; alternative filters and projection still need selective validation. A known season returned public `visible:true` and `active:true`, but `leaderboardPaused` returned `UNAUTHENTICATED`.

## Access and follow-up boundary

Clairvoyance's paced guesses against the older endpoint found no further Profile, Play or Replay field names in this pass. On the new endpoint it mistakenly accepted an invalid sentinel because an HTTP 200 response contained a GraphQL error; that candidate output was discarded. Full introspection provides a stronger and complete name inventory for this endpoint. The productive remaining work is to validate high-value fields on a few public profiles, runs and task IDs, pacing requests and honoring any rate-limit response. No HTTP 429 occurred in this pass. The raw SDL and delta preserve names and types where public runtime access fails. Do not build user-facing Athena or account features from a schema-only discovery.
